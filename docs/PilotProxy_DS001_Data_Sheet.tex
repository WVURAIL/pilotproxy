\section*{Introduction}
PilotProxy measures ATSC 1.0 DTV pilot tones with a fixed-point CUDA local-reference power-ratio detector. We use the narrow pilot as a proxy for a DTV data shelf that may lie below the broadband noise floor. The package includes the CUDA kernel, a public C API, Python wrappers, a precomputed ATSC weight bank, and a GNU Radio validation testbench.

The detector core is receiver-independent. The standalone testbench supplies its own reference front end, while the CHIME workflow supplies instrument metadata and packed telescope data through a separate adapter. This boundary keeps receiver assumptions out of the CUDA kernel without claiming that real-data operation is instrument-independent.

ATSC A/53 Part 2 specifies that the 8-VSB pilot is approximately 11.3 dB below the average data-signal power \cite{atsc_a53_part2_2011}. We record the positive magnitude of this relationship as \(\mathrm{pilot\_below\_data\_db}=11.3\dB\). Host software uses it to convert one-bin pilot excess to an equivalent DTV data-shelf SNR.

\subsection*{Features}
\begin{itemize}
  \item Fixed-point CUDA detector for ATSC 1.0 pilot excess.
  \item Compile-time 64- or 128-sample detector rows using packed complex
        4+4 bit input; the shipped CHIME bank selects 128.
  \item Three matched-filter terms: target pilot bin, lower reference bin, upper reference bin.
  \item Exact \code{uint64} fine powers per term and fine bin; the target/reference frame powers are their all-bin sums.
  \item Time-coherent front end: \code{int32} row sums, padded fine
        spectrum, rank-based marker detection.
  \item Synthetic-evaluator detection by an exact integer rational threshold comparison on the host; no division in that mask path.
  \item Synthetic-evaluator threshold coordinate is DTV shelf SNR in dB.
  \item The corresponding threshold coordinate is a rational power-ratio half-threshold.
  \item GNU Radio ATSC 1.0 waveform generation, audit, AWGN injection, quantization, and SNR evaluation.
  \item Physical-channel helpers and shipped weights for U.S. UHF channels 14-36.
\end{itemize}

\section{General Description}

The DTV data shelf occupies most of a nominal 6 MHz channel, but the ATSC pilot is narrow. Therefore, we measure the pilot against two nearby reference bins and use that excess to estimate the equivalent data-shelf SNR. This estimate is conditional on the stated bandwidth, pilot-to-data relationship, and pilot-capture efficiency.

The CUDA kernel implements only the fixed-point measurement. It receives a row-major detector matrix and three packed weight vectors. It returns the exact \code{uint64} fine powers of the three terms and the frame powers, their all-bin sums; the fused mask entries also return the per-frame mask bit of the fine decision. Host software applies the coarse threshold comparison in exact integer arithmetic and supplies the ATSC frequencies, dB conversions, receiver geometry, and physical-channel interpretation.

\section{Signal Definitions}

\subsection{Raw F-Statistic}

For one evaluated frame, the kernel produces three frame powers:
\begin{equation}
  P_t,\qquad P_{r1},\qquad P_{r2},\qquad
  P_n=\sum_{f}S[n,f],
\end{equation}
each the exact \code{uint64} all-bin sum of that term's fine power spectrum
\(S[n,f]\) (Section~\ref{ssec:fine}; kernel core 3.0.0). The target term \(P_t\) is centered on the ATSC pilot. The lower and upper reference terms, \(P_{r1}\) and \(P_{r2}\), sample the nearby non-pilot floor. We form the raw power ratio as
\begin{equation}
  \boxed{F=\frac{2P_t}{P_{r1}+P_{r2}}.}
\end{equation}
The fine-transform length cancels in this ratio. The library forms no ratio:
host code receives the three exact powers and must use
\(F=2P_t/(P_{r1}+P_{r2})\). Using \(P_t/(P_{r1}+P_{r2})\) would omit the factor of two in the detector definition.

\subsection{Pilot Excess and PNR}

The raw power ratio level is:
\begin{equation}
  R_F=10\log_{10}F.
\end{equation}
This level is not the physical pilot-to-noise ratio because \(F=1\) is the uncorrected no-excess point. We define the corresponding raw pilot excess as
\begin{equation}
  \boxed{\rho=F-1.}
\end{equation}
Physical pilot excess uses the exact packed-weight normalization,
\(\mu_0=2\lVert w_t\rVert^2/(\lVert w_{r1}\rVert^2+\lVert w_{r2}\rVert^2)\):
\begin{equation}
  e=F/\mu_0-1,\qquad
  \boxed{\mathrm{PNR}_{\mathrm{bin},dB}=10\log_{10}e.}
\end{equation}
The raw excess \(\rho\) is diagnostic only. For \(e\leq0\), the logarithm is
undefined and JSON reports encode it as \code{null}; the signed linear excess
remains available. \(\mu_0\) is a ratio of expected powers under flat noise,
not the finite-sample expectation of the random ratio \(F\).

\subsection{DTV Shelf SNR}

We define the DTV data-shelf SNR as the ATSC data-and-sync shelf power spectral density relative to the non-DTV noise floor. The pilot is not part of the shelf numerator. For the standard conversion, we compute
\begin{equation}
  \boxed{\mathrm{SNR}_{\mathrm{shelf},dB}=
  \mathrm{PNR}_{\mathrm{bin},dB}
  -10\log_{10}\left(\frac{B_{\mathrm{DTV}}}{B_{\mathrm{bin}}}\right)
  +\mathrm{pilot\_below\_data\_db}
  -10\log_{10}(\eta_p).}
\end{equation}
The default constants are:
\begin{equation}
 B_{\mathrm{DTV}}=6\,\mathrm{MHz},\quad
 B_{\mathrm{bin}}=3051.7578125\,\mathrm{Hz},\quad
 \mathrm{pilot\_below\_data\_db}=11.3\dB,
 \quad \eta_p=1.0.
\end{equation}
For these constants, the bandwidth spreading term is
\begin{equation}
  10\log_{10}\left(\frac{6\times 10^6}{\ppDetectorBinHz}\right)=\ppBandwidthSpreadDb\dB.
\end{equation}

\subsection{Time-Coherent Fine Statistic}
\label{ssec:fine}

The time-coherent front end replaces the reduction after the dot product:
instead of squaring each window's dot product and summing incoherently over
all rows, the windows are integrated coherently and only the feed sum
remains incoherent, recovering up to \ppCoherentGainDb~dB of deflection
sensitivity for \(W=128\) windows (\(10\log_{10}\sqrt{W}\), less
scalloping). For each weight term
\(n\in\{t,r1,r2\}\) and detector row \(m\), it returns the complex dot
product
\begin{equation}
  z[n,m]=\sum_{k=0}^{K-1} w_n[k]\,x_m[k]
  \qquad(\text{exact \code{int32} components}).
\end{equation}
The fine stage reshapes each term's rows to
\([N_{\mathrm{streams}},\,W]\) with \(W=\mathrm{frame\_size\_samples}/K\)
windows per stream, applies the frozen fixed-point FFT (\code{fxfft256_v1})
along the window axis with \(\times\ppFinePadFactor\) zero padding, and sums
incoherently over streams:
\begin{equation}
  S[n,b]=\sum_{\mathrm{streams}}\bigl|\mathrm{FFT}_{\mathrm{pad}}(z[n,\cdot])[b]\bigr|^2,
  \qquad
  \boxed{F_2[b]=\frac{2\,S[t,b]}{S[r1,b]+S[r2,b]},}
\end{equation}
for \(b=0,\ldots,\ppFineNumBins-1\) fine bins of width \ppFineBinHz\ Hz
(the detector-bin width divided by \ppFineNumBins). The reduction is
coherent in time within one frame and incoherent across streams and frames.
No inter-window phase corrector is required: each term's steering frequency
is an integer bin of the \(K\)-sample window, so an offset tone's
window-to-window phase survives stage 1 exactly
(\(e^{2\pi i c_n j}=1\) for integer bin \(c_n\)). The omitted
\emph{intra-window} fine rotation \(e^{-2\pi i kb/(\mathrm{pad}\cdot WK)}\)
is the window capture factor documented in \code{docs/METHOD_SPEC.md}
(\(\mathrm{sinc}^2\) scalloping: \ppCaptureLossThreeHundredDb~dB at
300\,Hz, at most \ppCaptureLossEdgeDb~dB at the fine-span edge). The frame
powers of the coarse statistic are \emph{defined} as the all-bin sums of this
spectrum, \(P_n=\sum_b S[n,b]\) (kernel core 3.0.0), so \(F\) is exactly the
all-bin marginal of the fine spectrum and no second power path exists; each
product stores both and the readers check \(P_n=\sum_b S[n,b]\) exactly. The
rounded fixed-point transform does not conserve energy exactly, so \(P_n\) is
not \(\mathrm{pad}\cdot W\sum_m|z[n,m]|^2\): the two agree to a median
relative \(3\times10^{-6}\) on archive frames and depart by up to about 2 per
cent on near-empty frames. Earlier cores computed that row-domain sum as a
separate power and enforced a per-frame marginal identity against it; both
are retired. The runtime fine decision compares the largest marker-bin ratio with a
calibrated multiple of a bulk order statistic. The archive also stores
any-bin diagnostic tests. The stored fields, calibration modes, and
detection-list layout are specified in
\code{docs/PRODUCT_SCHEMA.md}.

\subsection{Distributional Statement (Null Hypothesis)}
\label{ssec:dist}

Under the null hypothesis --- no pilot, a locally flat spectrum across the
three terms, and circular complex Gaussian channelized noise --- each
term's dot product \(z_n\) is complex Gaussian, so each per-row power
\(|z_n|^2\) is a scaled \(\chi^2_2\) variable, and the three terms are
independent because they sample disjoint detector bins. For one detector
row with equal term norms, write \(|z_t|^2 = \tfrac{s}{2}U\) and
\(|z_{r1}|^2+|z_{r2}|^2 = \tfrac{s}{2}V\) with \(U\sim\chi^2_2\),
\(V\sim\chi^2_4\), and a common scale \(s\); then
\begin{equation}
F_{\mathrm{row}}
= \frac{2\,|z_t|^2}{|z_{r1}|^2+|z_{r2}|^2}
= \frac{2U}{V}
= \frac{U/2}{V/4}
\;\sim\; F(2,4),
\end{equation}
the F distribution with \((2,4)\) degrees of freedom: a 2-dof power over
the mean of two independent 2-dof powers. This F law is an idealized reference, not a distributional claim for the
production detector or its rank-normalized fine score.

The ideal frame statistic sums powers over \(M\) rows before the ratio
(\code{all_rows_summed_before_ratio}), which replaces \((2,4)\) by
\((2M,\,4M)\): under the same assumptions \(F \sim F(2M, 4M)\). The frame
powers are the all-bin sums of the fine spectrum, which an exact transform
makes \(\mathrm{pad}\cdot W\) times the row sums in every term, so the same
distribution holds up to the fixed-point rounding of the transform. Two
location facts prevent a common misreading. The per-row \(F(2,4)\) has
mean \(4/(4-2)=2\) and a heavy right tail; the frame statistic with
\(M=\ppChimeRowsPerFrame\) rows concentrates tightly, with
\(\mathrm{E}[F(2M,4M)] = 4M/(4M-2) \to 1\). The mask's zero point
\(\mu_0\) is the ratio of expectations \(2 n_t/(n_{r1}+n_{r2})\) evaluated
with the exact quantized norms --- the value the concentrated frame
statistic approaches --- and the mask itself relies on no distributional
form at all: it is an exact integer comparison against \(\mu_0\).

Caveats, stated rather than assumed: with unequal reference norms, the
denominator is a weighted sum of two \(\chi^2_2\) terms and the \(4M\)-dof
form is a Satterthwaite-style approximation; correlated or non-Gaussian
interference violates the row-independence assumption. Each fine bin
repeats the construction across \(N_{\mathrm{s}}\) streams,
\(F_2[b] \sim F(2N_{\mathrm{s}},\,4N_{\mathrm{s}})\) on independent bins
under \(H_0\); the fine score instead normalizes marker ratios by a bulk order statistic.
That normalization alone does not certify a false-alarm rate; calibration
requires an appropriate independent noise population.

\section{Threshold Interpretation}

For synthetic threshold tests, the user supplies \code{threshold_data_shelf_snr_db}. Host software converts this shelf-SNR threshold to the raw power ratio coordinate and then to a rational half-threshold, which it applies to the integer frame powers:

\begin{align}
\mathrm{PNR}_{\mathrm{bin,thr},dB} &= S_{\mathrm{shelf,thr},dB} - \mathrm{pilot\_below\_data\_db} + 10\log_{10}(B_{\mathrm{DTV}}/B_{\mathrm{bin}})+10\log_{10}(\eta_p),\\
\rho_{\mathrm{thr}} &= 10^{\mathrm{PNR}_{\mathrm{bin,thr},dB}/10},\\
F_{\mathrm{thr}} &= 1+\rho_{\mathrm{thr}},\\
T_{\mathrm{half}} &= \frac{F_{\mathrm{thr}}}{2}=\frac{N_{\mathrm{half}}}{D_{\mathrm{half}}}.
\end{align}
The host evaluates, in exact integer arithmetic:
\begin{equation}
  P_t D_{\mathrm{half}} > N_{\mathrm{half}}(P_{r1}+P_{r2}).
\end{equation}
Exact equality is not a positive detection. The synthetic threshold path and the CHIME positive-excess path both use a strict greater-than comparison.


\notebox{We independently recomputed the following example from the checked-in conversion code. For a \(-26\dB\) shelf-SNR threshold and the included reference geometry, \(\mathrm{PNR}_{\mathrm{bin}}=-4.363988\dB\), \(F_{\mathrm{thr}}=1.36610123\), and \(T_{\mathrm{half}}\approx0.68305\).}

\section{Channel and Frequency Support}

The shipped weight bank covers U.S. physical channels 14 through 36. The eCFR assigns channel 14 to 470--476 MHz and channel 36 to 602--608 MHz \cite{ecfr_73603}. Following the ATSC pilot offset, the default channel-14 target is 470.309441 MHz.

\begin{longtable}{|C{0.13\linewidth}|C{0.18\linewidth}|C{0.20\linewidth}|C{0.33\linewidth}|}
\hline
\textbf{Physical channel} & \textbf{Lower edge} & \textbf{Pilot} & \textbf{Coarse index: ascending reference / shipped CHIME}\\ \hline
14 & 470.000 MHz & 470.309441 MHz & 179 / 843, lower reference edge wrapped\\ \hline
21 & 512.000 MHz & 512.309441 MHz & 287 / 735\\ \hline
36 & 602.000 MHz & 602.309441 MHz & 517 / 505\\ \hline
\end{longtable}

The first index is the standalone ascending-frequency reference coordinate. The second is the post-spectral-sense-normalization coordinate stored in the shipped CHIME manifest and printed by \code{pilot-proxy list-channels}. The nominal references are two detector bins below and above the target. In the shipped DC-centered bank, physical channel 14 is the only adaptive case: its target lies near a coarse-channel boundary, so the generated layout wraps the lower reference across the circular coarse-channel spectrum while preserving the two-bin offset, and \code{list-channels} prints the corresponding placement \code{NOTE}. No shipped channel collides with, or shifts around, the forbidden coarse-channel DC tone. Detection and validation reports copy the selected manifest row into \field{selected_weight_layout}, so this placement remains visible in each result.

\section{Receiver Integration Contract}

The CUDA detector core does not interpret receiver metadata. A receiver adapter must supply the following metadata and arrays above the kernel boundary:
\begin{itemize}
  \item \code{DetectorCoreProfile}: locked kernel contract, including the
        selected \(K\in\{64,128\}\), \(N=3\), int4 packed input, uint64
        fine and frame powers, and no threshold input.
  \item \code{ReceiverProfile}: RF band, channelizer geometry, spectral sense, baseband frame convention (\field{baseband_frame.channel_center_normalized}), frame size, input-stream count, quantization defaults, detector-bin ENBW, and pilot-capture efficiency.
  \item \code{stream_map}: stream-index metadata for feed, polarization, beam, or other receiver paths.
  \item \code{check-profile}, \code{check-layout}, \code{make-weights}, and \code{chime-run} consume the applicable profile or stream-map records. The standalone \code{detect} command selects shipped weights from its sidecar or channel flag, while \code{evaluate-snr} uses the fixed testbench geometry.
\end{itemize}

After this adaptation, the kernel receives only packed rows and packed weights, and it writes uint64 powers and a mask. For one selected DTV channel, the adapter constructs
\begin{equation}
N_{\mathrm{rows}} = N_{\mathrm{input\ streams}}\,
\frac{\mathrm{frame\_size\_samples}}{K}.
\end{equation}
The default combine mode is an incoherent power sum over streams. We sum the powers before forming the statistic:
\begin{equation}
F = \frac{2\sum_r P_{t,r}}{\sum_r P_{r1,r}+\sum_r P_{r2,r}},
\end{equation}
where \(r\) indexes detector rows. The result schema names this rule \code{all_rows_summed_before_ratio}. Per-stream packing remains available for integration diagnostics, but the combined detection path forms one \(F\) only after summing all selected rows.

The frame size is not a free detector parameter: the adapter matches the correlator's frame, and the kernel requires that value to be a positive multiple of the profile-selected \(K\). The checked-in \code{chime_dtv_fengine} receiver profile selects \(K=\ppDetectorWindowSamples\) and uses \(2^{14}=16{,}384\) channelized samples per input stream --- the CHIME F-engine upgrade frame this integration is designed for --- and declares the frame-verified DC-centered baseband convention (\field{baseband_frame.channel_center_normalized}=0.0), validated against archived CHIME baseband; the earlier half-band bank is not shipped and must not be deployed. For this profile and one selected coarse channel, \(\ppChimeStreams\times\ppWindowsPerStream=\ppChimeRowsPerFrame\) detector rows form one frame. The CHORD profiles instead select \(K=64\) with an 8,192-sample frame; both profile families retain 128 windows per stream for the frozen fine transform. The frame sizes are integration contracts, not claims about a universally deployed correlator frame. The software does not infer one universal value from HDF5 metadata: \code{chime-run} accepts an explicit per-run frame-size override, while \code{chime-scan} takes \code{nfft} from the Pilot Proxy CHIME instrument configuration. Operators must verify and record the resolved value for each real-data product.

\section{Result Schema and Mask Convention}

Detector and synthetic SNR-evaluator JSON outputs include a versioned \field{result_schema} object with \code{schema_version=pilotproxy_result_schema_v2}. This object records the statistic definitions, layout metadata, calibration constants, threshold fields, fixed-point contract, and mask convention needed to interpret those results. Audit, quantization, summary, injection, and CHIME products use their own documented top-level schemas rather than this object.

The fixed-point contract records:
\begin{itemize}
  \item \field{detector_window_samples} equal to the profile-selected 64 or
        128 (128 for the shipped CHIME bank);
  \item \field{reference_offset_bins=2} nominally, with \field{skipped_guard_bins=1} and adaptive placement metadata copied from the weight manifest;
  \item \field{packed_complex_bits=8};
  \item \field{sample_bits_per_component=4};
  \item \field{power_accumulator=uint64}.
\end{itemize}

For products that average masked data, we use exclusion masking:
\begin{equation}
\bar{P}_{\mathrm{after}} =
\frac{\sum_b P_b(1-M_b)}{\sum_b (1-M_b)}.
\end{equation}
Here \(M_b=1\) excludes block \(b\). We divide by the number of retained blocks rather than replacing excluded blocks with zeros.

The CHIME mask does not use a mean estimated from CANFAR data. For each fixed-point weight row, the weight norms define the flat-floor null point
\begin{equation}
\mu_0=\frac{2\,\lVert w_t\rVert^2}{\lVert w_{r1}\rVert^2+\lVert w_{r2}\rVert^2}.
\end{equation}
The basic uncorrected convention would call \(F>1\) positive excess. The current implementation instead masks a valid CHIME frame only when \(F>\mu_0\), evaluated by integer cross multiplication. Independent recomputation over the shipped manifest gives \(\mu_0\in[\ppMuZeroMin,\,\ppMuZeroMax]\) across the \ppWeightChannelCount\ channels. This correction accounts for unequal norms introduced by int4 weight quantization; it is not an empirical RFI threshold and does not establish an operational false-positive rate.

The operating point itself is carried as per-channel rational data in the
runtime bundle (\field{positive_excess_half_threshold_num},
\field{positive_excess_half_threshold_den}); the host applies it to the
frame powers and the kernel takes no threshold, so recalibrating the recorded
rule is a bundle regeneration alone, with no kernel or schema change. The active archive
decision remains the norm-corrected coarse positive-excess comparison above.
The implemented fine designated-set CFAR is a candidate whose calibration
status is \code{pending_campaign}; its spectrum, threshold, and exceedances are
diagnostic and do not set \field{reject_mask}. Because
\field{coarse_power_ratio} and the fine spectrum are persisted per frame,
previously recorded epochs can be re-scored offline after a separately
versioned policy is calibrated and adopted.

CHIME per-pilot archive products use
\field{schema_version}=\texttt{\ppPerPilotSchema}: the complete shared array
set plus the fine-reduction fields (fine spectrum, CFAR calibration columns,
and the ragged any-bin detection list). \code{docs/PER_PILOT_PRODUCT_FIELDS.md}
defines the shared arrays, \code{docs/FINE_REDUCTION_PRODUCTS.md} defines the
fine-reduction fields, and \code{docs/PRODUCT_SCHEMA.md} defines their active,
diagnostic, and candidate decision roles. The shipped weight bank and manifest are
identified by SHA-256 prefixes \texttt{\ppWeightBankShaShort} and
\texttt{\ppWeightManifestShaShort}.

\section{Reference PFB and Detector Resolution}

The standalone testbench uses the following reference channelizer:
\begin{itemize}
  \item real ADC sample rate: 800 MS/s;
  \item modeled band: 400 MHz bandwidth;
  \item PFB: 4 taps, 2048-point real input;
  \item usable positive-frequency channels: 1024;
  \item coarse-channel spacing: \(800\,\mathrm{MHz}/2048=390.625\,\mathrm{kHz}\);
  \item detector-bin spacing: \(\ppCoarseSpacingkHz\,\mathrm{kHz}/\ppDetectorWindowSamples=\ppDetectorBinHz\,\mathrm{Hz}\);
  \item padded fine-bin spacing: \(\ppDetectorBinHz\,\mathrm{Hz}/\ppFineNumBins=\ppFineBinHz\,\mathrm{Hz}\).
\end{itemize}
These values define the tested reference geometry. In particular, the default SNR conversion uses the resulting \ppDetectorBinHz\ Hz detector-bin width. A receiver with a different effective noise bandwidth must provide its own value. Throughout this document, ``detector bin'' names the \ppDetectorBinHz\ Hz resolution set by the \(K=\ppDetectorWindowSamples\) window, and ``fine bin'' names the \ppFineBinHz\ Hz resolution of the padded window-axis FFT.

\section{Data Format}

Each input sample is one \code{int8_t} containing a packed complex int4 value:
\begin{equation}
  \text{bits }[7:4]=\mathrm{real},\qquad \text{bits }[3:0]=\mathrm{imag}.
\end{equation}
We decode each nibble as two's-complement signed int4 with range \([-8,7]\). The generated weights use the symmetric range \([-7,7]\), which avoids the unmatched negative endpoint when generating detector ROMs.

Input matrices are row-major:
\begin{equation}
  \mathrm{d\_in}[m,k]=\mathrm{d\_in}[mK+k],\qquad K\in\{64,128\}.
\end{equation}
For batched input:
\begin{equation}
  \mathrm{d\_in}[b,m,k]=\mathrm{d\_in}[(bM+m)K+k].
\end{equation}

\section{Fixed-Point Sizing}

The int4 growth bound limits the supported detector windows to 64 or 128
samples. We conservatively bound one real or imaginary complex-product
component by 128 per tap. Therefore, the largest supported window, 128 taps,
has an absolute component bound of 16,384 and fits in signed 16-bit storage; a
256-sample window could reach 32,768 and exceed the positive signed-int16
limit. Under the same bound the fixed-point transform stays inside
\code{int32}, the feed-summed fine powers fit in \code{uint64}, and so do
their all-bin sums, the frame powers: with \(R=16{,}384\),
\(P_n\le 256\cdot 2R^2\cdot W\cdot N_{\mathrm{streams}}\cdot 1.001\), about
\(2^{55}\) at 2048 streams and \(2^{60}\) at the 65,536-stream capacity the
build asserts (the factor 1.001 bounds the fixed-point transform's departure
from Parseval at these amplitudes; \code{cuda/config.h}).

A zero reference denominator cannot define \(F\). The host therefore forces the mask to zero and marks the frame invalid; Python callers must inspect \field{p_ref_sum_u64} (or \field{valid}) before interpreting any conversion. The outputs serve three roles. Deployment consumes only the per-frame
\code{mask} (1 = reject, 0 = keep); in the proposed Kotekan interface, this
bit is the entire queue payload. The science-product path consumes the exact

--- the archive pipeline forms the norm-corrected decision on the host and
stores the statistic --- and the exact \code{int32} row sums, the input to
the fine spectrum, through an optional debug tap; none of these cross the
deployment interface.

\section{Limitations}

\begin{itemize}
  \item Installed wheels and sdists carry the weight bank and \code{configs/} resources; default-resource commands such as \code{list-channels} work outside the repository. Workflows that use repository-relative generated paths, helper scripts, a second Python interpreter, or the CUDA build require a checkout or explicit paths. The CUDA kernel is not packaged and builds from the cloned source tree.
  \item The CUDA API is default-stream only.
  \item The shipped weight bank covers physical channels 14-36 only.
  \item Standalone validation models ATSC 1.0 signals generated with GNU Radio. It does not by itself validate telescope performance.
  \item The CHIME baseband workflow is implemented in \code{pilot_proxy.chime} and documented by its runbooks. The checked-in 16,384-sample profile represents the planned Engine upgrade interface and remains subject to run-metadata verification.
  \item Receiver profiles define an adapter contract; they do not establish that a telescope pipeline has been deployed or validated.
  \item The CHIME mask uses $F>\mu_0$, where $\mu_0$ comes from fixed weight norms. It is not a threshold fitted to telescope null statistics, and no operational false-positive rate is claimed.
  \item The kernel measures pilot excess. It does not decode an ATSC transport stream or prove that every excess is DTV.
  \item Fine products are mandatory: the frame powers are the all-bin sums of the fine powers, so a library without the row-sum and fine-power entries cannot produce a product. \code{fine_products} accepts only \code{on}; \code{off} and \code{auto} are refused.
  \item On DTV-occupied channels, a real pilot at a nonzero frequency offset occupies non-designated fine bins; an elevated non-designated flag rate can therefore be signal rather than CFAR miscalibration. The stored fine spectrum resolves which.
  \item Standard conversion uses the ATSC 11.3 dB relationship. Any calibrated override must be recorded with the result that used it.
\end{itemize}
